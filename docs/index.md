# Учебная практика

**ПМ.07 Соадминистрирование и автоматизация баз данных и серверов**

Итоговая работа практики: **рабочая виртуальная машина с установленной СУБД** и **одним скриптом автоматизации**, который выполняет рутинную операцию администратора по расписанию.

## Цель практики

Сформировать базовые навыки администрирования сервера баз данных: установить и настроить СУБД, создать пользователей и роли с нужными правами, выполнить резервное копирование и восстановление, написать простой скрипт автоматизации одной рутинной задачи и поставить его на расписание.

## Задачи

1. Развернуть виртуальную машину с указанной операционной системой.
2. Установить СУБД из варианта и убедиться, что сервис запущен.
3. Подключиться к серверу из консольного клиента и через GUI (DBeaver, MySQL Workbench, pgAdmin, SSMS).
4. Создать рабочую базу выбранной предметной области и наполнить её 2–3 таблицами с тестовыми данными.
5. Создать не менее трёх пользователей с разными ролями: `admin`, `app_user`, `readonly`.
6. Проверить, что каждый пользователь видит и может делать только то, что разрешено.
7. Выполнить ручной бэкап базы и сохранить файл вне рабочей папки СУБД.
8. Удалить или повредить таблицу и восстановить её из бэкапа.
9. Написать скрипт автоматизации одной рутинной задачи (по варианту).
10. Поставить скрипт на расписание (cron или Планировщик заданий).
11. Заполнить журнал администратора по шаблону и собрать отчёт по практике.

## Минимальные требования к итоговой работе

| Блок | Минимальное содержание |
|------|------------------------|
| Виртуальная машина | Гость загружается, есть сетевое подключение к хосту по фиксированному IP или через port forwarding |
| СУБД | Сервис запущен; команда статуса возвращает `active (running)` или `Running`; порт открыт |
| Конфиг | В одном файле зафиксированы порт, путь к данным, кодировка (UTF-8) |
| Пользователи | 3 учётных записи: `admin` (DBA), `app_user` (CRUD), `readonly` (SELECT) |
| Права | `readonly` не может удалить запись; `app_user` не может создавать пользователей |
| Бэкап | Файл `backup_*.sql` или `backup_*.dump`; размер > 0; внутри есть DDL и DML тестовых таблиц |
| Восстановление | После повреждения таблицы данные возвращаются из бэкапа без потерь |
| Скрипт | Один файл; читает параметры из переменных; пишет лог в отдельный файл; выходит с правильным кодом возврата |
| Расписание | Скрипт автоматически запустился хотя бы один раз; в журнале есть запись о запуске |
| Журнал | По форме «дата · действие · команда · результат» |
| Документация | README с порядком запуска и ссылками на конфиги |
