# Список предметных областей

## Как пользоваться списком

Номер назначает преподаватель. Сохранены тридцать разных сочетаний области, ОС, СУБД и операции автоматизации. В каждой карточке есть собственный SQL-файл с исходными строками. Выберите один маршрут по ОС и СУБД; схема из SQL уже дана, повторно проектировать её по другой практике не требуется.

Обозначение `NN` заменяется двузначным номером. Даты в контрольных SQL — фиксированные учебные данные: **дата отсчёта 04.11.2026**. Для проверки временных границ используйте эту дату, а затем отдельно объясните замену на текущую дату планового запуска.

Все предметные таблицы содержат поля id, name, event_at, amount, link_id, quantity, expires_on. Это компактные исходные данные для освоения администрирования, а не полная производственная модель области. Поле link_id связывает записи для учебных запросов; автоматическая последовательность id не используется. Исходно в каждой предметной таблице 4 строки, SUM(id)=10, SUM(amount)=100. Дополнительная access_probe содержит одну проверочную строку.

Каркас скрипта и назначение его параметров находятся в выбранном маршруте. Функция из карточки заменяет только одноимённую функцию каркаса. В примерах до выполнения заменяются DB, пути и имена из таблицы подстановок маршрута; остальные команды другого движка не используются.

run_task() {

run_task() {

    for file in "$WORK/backups/${DB}_"*.sql; do

### Индивидуальная операция

### Точная вставка в каркас

В run.sh или run.ps1 удалите только пустую функцию run_task / Invoke-Task и вставьте приведённую функцию целиком. Строки подключения, логирования и вызова функции из каркаса сохраняются. Временные границы объяснены в проверке ниже.

```bash
run_task() {
if /usr/sbin/service "$DB_SERVICE" status >/dev/null 2>&1; then
        log INFO "service already active"
    else
        /usr/sbin/service "$DB_SERVICE" start >> "$LOG" 2>&1
        /usr/sbin/service "$DB_SERVICE" status >> "$LOG" 2>&1
        log INFO "service started"
    fi
}
```

### Проверка своего результата

Проверьте два состояния только выданной службы учебного сервера: уже запущена и остановлена. Во втором случае после операции она работает, а подключение к БД снова выполняется. service — стандартная команда Ubuntu и Debian: она обращается к службе systemd либо к выданному init-скрипту. Полный путь /usr/sbin/service сохраняется и при запуске cron. У учётной записи ОС должно быть выданное право запуска этой службы; отказ в праве — ошибка опыта. В отдельной тестовой копии конфига задайте DB_SERVICE="pm07_no_such_service": ожидаются ERROR и ненулевой код. Остановку общей службы организации эта карточка не предусматривает.

function Invoke-Task {
$File = Join-Path $Work "backups\$($Database)_$Stamp.bak"
