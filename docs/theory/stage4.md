# Операция, скрипт и расписание

## Три разных результата

Команда выполняет операцию. Скрипт задаёт параметры, проверяет ошибку и сохраняет журнал. Планировщик запускает скрипт в заданное время от конкретного пользователя ОС. Сохранённое расписание ещё не подтверждает, что команда действительно выполнилась.

## Что делает каркас

Каркас знает рабочую папку и профиль выбранного клиента, создаёт собственные out/backups/logs, записывает START, вызывает ровно одну функцию варианта и при успехе записывает END. При ошибке возвращается ненулевой код. Незаменённая функция-заглушка завершает работу ошибкой, чтобы пустой каркас нельзя было принять за готовый вариант.

## Код и фактический результат

В Bash ошибка важной команды должна прервать обычную ветвь; в PowerShell внешний exe дополнительно проверяется по LASTEXITCODE. Наличие TRY/CATCH само по себе не превращает любой ненулевой код внешней программы в исключение. Поэтому каркас проверяет его явно.

## Контекст пользователя

При расписании могут отличаться текущая папка, PATH, парольный профиль и доступ к файлам. Ручной и запланированный опыт выполняются от одной выданной учётной записи. SQL Server пишет BACKUP от своей службы на серверной машине; PowerShell-клиент не становится владельцем этого файла автоматически. Экспортированный профиль одного пользователя Windows не подставляется под SYSTEM.

## Как проверить отказ

Меняется отдельная копия конфигурации, а не единственный рабочий парольный файл. Неверная база, отсутствующий входной файл или недоступный каталог должны дать понятный ERROR и ненулевой код. После исправления повторяется тот же опыт. «Файл появился» и «в логе написано OK» проверяются вместе с его содержимым.

## Как проверить время

Сначала назначается ближайший тестовый триггер. Нужно дождаться этого времени и сопоставить запись планировщика, новые строки журнала и результат операции. Ручная кнопка «Выполнить» не подтверждает срабатывание временного триггера. Затем одна тестовая запись заменяется постоянной с частотой своей карточки.

## Индивидуальное изменение

Выбор операции и дополнения описан в [списке областей](../subject_areas.md). Если проверка кода, конфигурация или INFO/ERROR уже присутствует в образце, её простое сохранение не является новым дополнением. Объясните конкретное изменение поведения и проверочный пример.
