    Соадминистрирование и автоматизация баз данных и серверов¶

    Полное задание¶

    Какой результат подготовить¶

    На выделенном учебном сервере выполните базовые операции администратора: подключение, разграничение доступа, ручную резервную копию, восстановление отдельной проверочной базы и запуск одной операции по расписанию. Операция автоматизации, ОС и СУБД указаны в карточке вашего варианта. Один вариант — один рабочий маршрут.

    С чего начать¶

    Найдите себя в списке своей группы. Откройте вариант с тем же номером в отдельном файле «Список предметных областей». По ОС и СУБД из карточки откройте один маршрут. Скачайте SQL-файл своего варианта и поместите его на учебную машину. Для подключения используйте выданный паспорт среды.

    Что должно быть выдано до начала¶

    Нужен отдельный учебный сервер или виртуальная машина с уже работающей СУБД своего варианта, консольным и графическим клиентами. Преподаватель передаёт адрес, порт, имя начального администратора сервера и способ входа, доступ к терминалу ОС, разрешённый каталог работы и способ переноса файлов. Для Windows дополнительно нужны пути к клиентским утилитам и учётная запись запуска планировщика. Для Linux — имя службы, доступность cron, тип и доступ к журналу его запусков. Для всех сред указывается часовой пояс сервера и планировщика. Запишите эти сведения в исходные условия без паролей.

    Установка ОС и СУБД не входит в обязательный маршрут этой методички. Если доступа или параметров подключения ещё нет, сообщите преподавателю номер варианта, ОС и СУБД и запросите доступ к подготовленной среде. До получения доступа можно скачать свой SQL-файл и открыть нужный маршрут. Команды выполняйте только в выданной учебной среде.

    Какие данные использовать¶

    В карточке своего варианта скачайте его SQL-файл с тремя учебными таблицами и контрольными строками. Этот файл уже задаёт структуру: проектировать ER-модель повторно не требуется. У каждого варианта своя база pm07_vNN. Таблица access_probe служит только для проверки прав. Числа, даты и имена в примере учебные; они не являются данными действующей организации.

    Для первого разбора дан отдельный SQL-образец «Учёт оборудования лаборатории». Он объясняет действие команд. Обязательный результат — собственный вариант; вторую демонстрационную работу сдавать не нужно. Не требуется выполнять все шесть маршрутов или все тридцать вариантов.

    В каком порядке работать¶

    1. Выберите маршрут по ОС и СУБД своего варианта. Проверьте адрес, порт, версию сервера и текущее имя пользователя.
    2. Под начальным администратором создайте учебную базу и три учётные записи. Пользователь admin управляет своей базой, app_user работает с данными, readonly только читает. Создание серверных учётных записей выполняется из-под начального администратора, а не из-под admin с правами только на одну базу.
    3. Загрузите готовый SQL своего варианта. Проверьте разрешённые и запрещённые действия отдельными подключениями. Запишите точную причину отказа.
    4. Сделайте ручную резервную копию, сохраните SHA-256 и контрольные значения. Восстановите отдельную базу pm07_vNN_restore. Исходная база при этой проверке сохраняется.
    5. Подготовьте один скрипт операции своей карточки. Сначала проверьте его вручную, затем назначьте ближайший однократный запуск и только после этого постоянное расписание.
    6. Сохраните журнал, фактические результаты проверок, скрипты и параметры запуска. Объясните одно индивидуальное дополнение, которого ещё не было в исходном образце.

    Что проверить и сдать¶

    Подтвердите подключение из CLI и графического клиента, матрицу прав, ручной бэкап, восстановление отдельной копии и результат назначенной операции. Для таблиц сравните количество строк и контрольную сумму числового поля; один ненулевой размер архива этого не подтверждает. SHA-256 проверяет неизменность файла, а не полноту восстановленных данных.

    Откройте в ZIP из карточки практики файл «Отчёт о выполнении проекта.docx». Заполните исходные условия, выполнение и проверку, итоговую проверку и сдачу. В форме есть места для результатов подключения, проверки прав, восстановления, своей операции, отказа и расписания, дополнения и передачи. Вставляйте собственные результаты и рисунки с подписями.

    Сохраните SQL настройки прав, скрипт автоматизации, журнал, контрольные значения до и после восстановления, резервную копию и параметры расписания. Подготовьте репозиторий и сдачу по шагам. Остальные формы возьмите из карточки своей группы.

    Файлы и выбор маршрута¶

    • Методические рекомендации, PDF.
    • Отдельный список предметных областей, PDF.
    • Бланк отчёта, DOCX. На сайте файл скачивается как «Отчет о выполнении.docx». В ZIP карточки этот же бланк называется «Отчёт о выполнении проекта.docx».
    • Тридцать карточек вариантов и собственные SQL-файлы.
    • SQL-образец для MySQL, MariaDB, PostgreSQL, SQL Server.
    • Выберите один маршрут. Указанные SQL-файлы — исходные данные, не готовые скрипты автоматизации.

    Как вести журнал¶

    Для каждого существенного действия записывайте: дату и время, ОС/клиент, учётную запись, базу, выполненную команду, ожидаемый результат, фактический результат и вывод. Сообщение о запрете — успешная проверка прав только тогда, когда отклонена нужная операция. Ошибка пароля, синтаксиса или отсутствующего файла не подтверждает разграничение доступа.

    Панель СУБД и консоль ОС — разные места выполнения. SQL вводится в клиенте выбранной СУБД; команды Bash — в терминале Linux; PowerShell — в окне Windows PowerShell. Метки приглашения mysql>, postgres=#, PS> и $ в команду не копируются.
